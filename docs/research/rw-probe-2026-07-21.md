## Dual-color (雙色字) — design note (not fully exercised live)

Big5 Chinese is **2 bytes per glyph**. Historical Chinese MUD clients (incl. zMUD-era tooling) often support **per-cell / mid-glyph color** where:

1. SGR can sit between the lead and trail byte of a DBCS character, or
2. A full-width glyph is painted as two half-cells with independent attributes.

Naive UTF-8 terminal pipelines that decode-then-color will either:

- break the glyph (mojibake / replacement char), or
- refuse dual-color and force monochrome full-width cells.

**Correct pipeline is byte-oriented until cellization:**

```
TCP bytes → Telnet IAC strip/negotiate → optional MCCP inflate
  → Big5-aware tokenizer (SBCS | DBCS lead+trail | CSI/OSC | MXP)
  → cells { grapheme_or_half, attrs }
  → render (DOM / canvas / xterm custom)
```

Full dual-color verification needs a captured in-game fixture (user session log or wizard sample). Track as Phase 1/3 acceptance, not assumed from banner alone.
